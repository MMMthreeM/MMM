# 材料需求管理平台 - 專案執行計畫

版本：程式同步版 v3.0
更新日期：2026-10-29（台灣時間）
本文件整合本次已確認需求、實作進度、部署與驗收待辦；功能細節以同目錄「材料需求管理平台 - 設計規格確認書.txt」為準。

一、交付原則

1. 手機優先，並改善桌機叫料及管理批次處理效率。
2. 依最新授權採墨藍 #245C75 主操作、森林綠 #2E6B4F 完成狀態，不再綁定先前品牌色碼；警示須同時有文字，不只依賴顏色。
3. 訂單以整張單據管理，材料為明細；勾選數以「張」計算。
4. 使用者的「自己」指所屬整個工班，不限本人建立的單據。
5. 權限、狀態、材料、數量及必要版本由後端驗證。
6. 未提供的單位、現行價格與工班對應不猜測；無法對應時提示確認。
7. 程式完成、本機測試、部署成功與正式服務驗收分開記錄，不以本機通過推定正式上線。

[x] 2. 角色首頁與導覽

    - 使用者首頁為整個工班的材料儀表板。

    - 草稿在歷史需求單獨立分頁，不另設頂層選單。

[x] 3. 手機申請流程重構
    - 「選擇材料 → 確認並送出」兩步驟。
    - 申請端隱藏廠商與材料編號；依分類、名稱、規格、標籤與別名搜尋，手機每頁 8 筆、1024px 起桌機每頁 24 筆。
    - 前後端驗證正整數、最低量與級距；支援其他自填材料。
    - 清單可新增、修改、移除；取消修改不遺失原項目。
    - 桌機限寬 1080px，材料與清單並排；數量加減集中於 240px 內。

[x] 4. 歷史需求單
    - 預設「進行中」，退回待修改優先，再待審核、審核中；提供狀態快捷篩選。
    - 草稿獨立；準備出貨、已送達集中「準備出貨／已送達」。
    - 可修改階段提供修改／刪除，鎖定單據可整單重訂。
    - 每頁 10 張，支援材料文字、日期與次要單號搜尋與返回最上方。

[x] 5. 審核中心、整單狀態與退回
    - 同單號的識別、工班、主要狀態只出現一次；勾選即整單全部材料。
    - 預設最近一個月，由後端限制日期回傳；可清除日期查舊單。
    - 材料／廠商篩選保留符合單據的全部明細，更換篩選清除勾選。
    - 後端驗證整單狀態／工班一致性、合法轉換及必要材料版本。
    - 整單退回可選共用原因或指定材料原因；整張狀態一起退回。
    - 有有效退回原因的處理中單據統一顯示「退回待修改」；重新送出後恢復待審核。
    - 待審數不混入退回待修改。
    - 管理員用編輯圖示修改處理中、審核中材料／數量／備註，可新增移除材料。
    - 管理編輯保留原申請人、工班、日期與進度；筆數變更以單次 Sheets 批次寫入完成。

[x] 6. 材料儀表板
    - 使用者看整個工班，管理者看全工班及指定工班匯總。
    - 材料、日期、狀態篩選；管理端另有工班條件。
    - 呈現需求單數、材料種類、常用材料、月份需求及材料／工班明細。
    - 草稿不列入；同單同名同單位頻率計一次，數量逐筆加總，不同單位分開。
    - 材料／工班明細每頁 20 筆；完整統計不受分頁影響。

[x] 7. 匯出與重匯

    - 勾選匯出：審核中會轉準備出貨；準備出貨、已送達可重匯，維持原狀態。
    - 伸泰、益詮各一份 .xlsx，提供 ZIP 與個別下載。
    - 沿用原始範本的固定工班欄、材料列與樣式，取消原版動態雙分頁設計。
    - 未叫料留空；同廠商同名同單位重複列匯總最上方列，其餘空白。
    - 系統「鶴峻」對應來源鶴峻／鶴竣欄；其他未知對應須確認。

現行介面與文件同步補充（2026-10-29，以本節取代前文任何舊介面描述）

1. 導覽與名稱
管理員選單以分隔線及標題區分「管理作業：管理工作總覽、材料審核中心、需求分析儀表板」與「工班作業：建立材料需求、歷史需求單」。一般使用者首頁為所屬工班材料需求儀表板。管理員的建立／歷史功能仍受所屬工班範圍限制，不等於管理端全工班資料。完整名稱見 docs/terminology.md。

2. 日期優先與材料閱讀
所有需求單以最近送出／更新時間為主、單號次要。日期搜尋支援 YYYY/MM/DD、YYYY-MM、YYYYMMDD；日期格式查實際日期，不誤查單號中的舊日期。單號仍可搜尋。儀表板及歷史需求單材料使用「品項：數量 單位」相連，保留數字千分位，避免桌機左右太遠而看錯行。歷史頁供應廠商為既有次要資訊；建立需求的選料與確認不顯示編號或廠商。

3. 儀表板
預設逐月趨勢；材料總覽、材料趨勢、管理員工班明細及期間訂單明細有各自用途。全材料顯示每月正式單數；選材料後依單位畫需求量，同名不同單位分圖，不自動換算。桌機按寬度安排月份刻度，手機每段六個月；全範圍已顯示則隱藏切換並標示總月數，分段時提供前後 N 個月與邊界文字。點月份只更新下方單月訂單，不變更原日期範圍。單月可轉期間訂單明細，保留整單，每頁十張。返回恢復原篩選、分頁與捲動位置，返回列採正常排列，不浮動覆蓋圖。工班端不重複顯示每單工班名，管理員保留。

4. 表單與通知
材料常用／最近偏好保存在帳號及工班範圍的目前瀏覽器，不是工班共同收藏。切換入口清除不適用的分類與搜尋條件；載入有動畫並尊重減少動態效果。未儲存離開有確認，瀏覽器返回等情境仍需獨立驗收，不宣稱全面攔截。正式新單、重送與草稿送出 TG 包含全部品項與數量，最後才放審核提醒；過長拆段，提醒只在最後一段。個人 TG 通知仍送原申請帳號。

5. 材料欄位擴充
I:N 分別為 Category、Subcategory、Search_Aliases、Order_Hint、Requires_Remarks、Display_Name；舊 A:H 仍相容。價格只在後端使用，不回傳前端；混合材料的必填備註前後端均驗證。早期 135 筆、缺單位與價格的整理紀錄為歷史交付，不代表目前正式材料總數；新版匯入步驟以 docs/material-catalog.md 與交付檔說明為準，不重複追加歷史單。

6. 清理及未實作
移除無引用且規則衝突的 lib/state-machine.ts 與五個 Next.js 預設 SVG；實際狀態規則仍在 lib/order-domain.ts。報表工具、舊網址相容、監控及管理員連線檢查保留。清理範圍見 docs/code-review.md。
加入手機主畫面不會把 Telegram 轉成平台通知。本輪未實作 Service Worker、Web Push 訂閱或離線送單；手機通知評估見 docs/notifications.md。四位隨機單號、Sheets 全表讀寫及跨請求交易限制維持原約定。
