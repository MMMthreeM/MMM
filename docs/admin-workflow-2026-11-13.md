# 管理員代下單、全階段編輯與手機進度（2026-11-13）

## 介面

- 案件卡片的「查看 N 筆材料、確認與歷史」展開列增加桌機 20px、手機 16px 內距及至少 48px 的操作高度，箭頭與文字不貼卡片邊緣。
- 手機需求進度保持四個階段同一水平列，不再排為兩列方塊。使用節點、階段名稱及目前階段提示，沿用原本狀態值。
- 管理員編輯每筆材料時直接提供共用 `MaterialPicker`：分類、細分類、關鍵字及材料選項與一般叫料相同。數量使用共用加減控制與最低量／倍數驗證，不須先進「更多」才能找選料。

## 指定工班代下單

管理員在建立需求或再訂一次時選擇「代下單工班」。選項來自目前 Users 中具有 User 角色的已登錄工班，地區依該工班設定帶入。相同工班若有互相衝突的地區，先從選項排除，待修正 Users 後再使用，不猜測地區。

最後確認顯示選定工班；建立需求與新草稿均將工班傳至後端。後端重新以經授權帳號取得的工班目錄核對，不接受任意公司或前端自行指定地區。Req_Company、Req_Region 為指定工班資料，Req_User 記錄實際操作管理員的 Nickname。

新需求第一次保存後維持原工班，不能在編輯原單時偷偷換成其他工班。管理員的工班需求／草稿查詢可讀取各工班資料，讓代理建立的草稿能繼續開啟；一般工班仍只能讀取所屬 Company。

## 全階段管理員編輯

前端與後端同時開放管理員對草稿、待審核、審核完畢、準備出貨、已送達單據進行材料修改。

- 編輯入口出現在各正式階段，草稿也能由工班需求入口編輯。
- 維持原單號、工班、需求日期、交期與狀態；編輯已送達單不會退回待審核。
- 有效退回保留，管理員修改不等於工班重新送出，也不會自行關閉退回。
- 維持整單版本／材料指紋、目前材料規則、逐筆核對、正式確認簽章、寫入鎖、稽核及未知結果不重送規則。
- 修改材料的數量仍須符合最低量與倍數；管理員也不能跳過後端驗證。
- 一般工班原有的可修改狀態及權限不變。
