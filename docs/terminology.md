# 功能命名對照（2026-10-29）

| 名稱 | 對應功能 | 範圍 |
| --- | --- | --- |
| 維運材料管理平台 | 產品名稱；英文 Maintenance Materials Management | 全站 |
| 管理工作總覽 | 待審、審核中、審核完畢與準備出貨工作佇列 | 管理員首頁 / |
| 材料審核中心 | 整單選取、狀態變更、退回、管理員編輯、報表匯出 | /admin |
| 趨勢分析儀表板 | 導覽入口；頁面標題依角色為各工班／所屬工班材料趨勢分析儀表板 | Admin /analytics；User / |
| 建立材料需求 | 選擇材料、確認並送出或儲存草稿 | /request |
| 歷史需求單 | 所屬工班正式需求與共享草稿；不等於管理員全工班歷史 | /dashboard |
| 材料總覽 | 目前篩選內的材料叫料頻率、數量與單位 | 儀表板 |
| 材料趨勢 | 每月正式單數，或選定材料的需求量；不同單位分圖 | 儀表板 |
| 工班明細 | 全工班／指定工班的單數、材料種類與最近需求 | 管理員儀表板 |
| 期間訂單明細 | 整個篩選日期範圍的相關完整需求單 | 儀表板 |
| N 年 N 月的需求單 | 趨勢圖選定月份、沿用材料／工班／狀態篩選 | 儀表板 |
| 開始審核 | 待審核轉為審核中；不是完成審核或出貨 | 管理員 |
| 匯出篩選範圍 | 匯出目前篩選內全部正式完整單，不變更狀態 | 管理員 |
| 完成審核 | 審核中轉審核完畢，全單材料需已指定有效供應商 | 管理員 |
| 設為準備出貨 | 審核完畢轉準備出貨，預計交期選填 | 管理員 |
| 材料／廠商對應 | 對應清單材料或保留自填規格，逐筆指定本次供應商 | 管理員 |
| 賀冠詢價 | 產生可編輯、可複製文字；不自動傳送、不推進狀態 | 管理員 |
| 匯出勾選單據 | 僅匯出所勾正式完整單據，各正式階段均維持原狀態 | 管理員 |
| 再訂一次 | 以舊單材料建立新需求，不修改原單 | 工班歷史 |
| 預計交期 | Expected_Date 選填，依廠商回覆為主；不代表保證送達日期 | 全站 |

原始狀態：編輯中→畫面「草稿」；處理中無有效退回原因→「待審核」；處理中有有效原因→「退回待修改」。其餘維持「審核中／審核完畢／準備出貨／已送達」。不新增已出貨、已完成或獨立退回狀態欄值。
管理員選單將管理作業與工班作業分區；趨勢分析是分析用途，歷史需求單是所屬工班的修改、送出、重訂用途。


## 2026-10-31：填單、地區與需求狀態一致性

- 文字叫料先逐筆確認，交貨備註及指定對象移到全部材料下方、加入清單按鈕上方。備註對象以獨立留白選項呈現，桌機兩欄、手機一欄；每筆的確認與略過位於同一操作區。最後指定交貨備註不取消已確認材料，加入前仍檢查合併備註長度及其他材料規則。
- 填單成功提示於下一次表單操作或步驟切換時清除。公告內容寬度與頁首一致，手機亦對齊。
- 管理員分析儀表板新增地區篩選；分析及審核皆先地區、再工班，變更地區會清除舊工班條件。分析下探返回會還原地區，切換條件重設分頁／月份範圍。
- 兩頁共用 lib/order-status.ts 的「需求狀態」選項及 lib/order-view.ts 整單篩選邏輯：全部正式需求、待審核、退回待修改、審核中、審核完畢、準備出貨、已送達、全部待處理（含退回）。草稿不納入正式分析／審核。
- 資料庫 Status 與 API 狀態值新增審核完畢，其餘維持既有值，編輯中顯示草稿；處理中無有效退回原因顯示待審核，有有效原因顯示退回待修改；[已重送] 舊原因不會算成退回。審核中／審核完畢／準備出貨／已送達維持原名，不新增已出貨或已完成狀態。網頁標籤、新單與進度 TG 通知、待審核提醒及新稽核摘要統一使用上述用語。
- 額外 UIUX、資安、效能建議僅列於 docs/optimization-review-2026-10-31.md，尚未實作。


2026-10-31 操作用詞與選料簡化：重訂按鈕統一為「再訂一次」，草稿入口為「開啟草稿」。移除常用材料、最近選用及收藏功能，保留分類／關鍵字選料、文字叫料、自填材料。文字叫料提示使用指定的電線、電纜、LED 燈泡及 ELCB 範例；範例只有提示，不會預先加入需求。


## 2026-11-13：目前進度與人員欄位

需求詳情、列表及篩選統一使用「待審核 → 審核完畢 → 準備出貨 → 已送達」。目前沒有獨立「審核中」；「管理審核／出貨準備」不再作為進度名稱，前文舊「開始審核」流程已被取代。退回仍另顯示「退回待修改」，資料值為處理中。

搜尋欄右側漏斗圖示的操作名稱為「進階篩選」。Orders.Req_User、Admin_User 使用 Users.Nickname；登入及原始稽核身分仍為 Email。新單號為 ORD-YYYYMMDD-NNNN，舊單號維持原值。
