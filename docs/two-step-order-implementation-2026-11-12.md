# 兩步下單 prototype 實作 — 2026-11-12

本次依使用者確認的 prototype 實作到本機 `/request`。本文件取代較早 `order-entry-ux-spec-2026-11-12.md` 中與「文字先加入共同清單、逐筆已核對」衝突的工班流程；管理員與後端寫入契約沿用既有實作。

## 實際行為

1. **選擇材料**：預設搜尋選料，填數量／備註後才加入待送出清單；保留數量加減、自填材料，以及未完成輸入的離頁提醒。桌面左右呈現選料表單與待送出摘要，手機單欄。摘要最多顯示最近五筆。
2. **貼上叫料文字**：按「分析叫料文字」後，結果留在分析區，不直接加入清單。每筆只有一個「略過」勾選，預設都不略過；略過項目不驗證也不加入。其餘項目須有明確材料來源及有效數量／必要備註。按「加入待送出清單（N 筆）」才加入；全部略過可完成本批次而不新增材料。
3. **確認並送出**：呈現完整材料名稱、數量／單位與實際備註，可修改、取消修改或移除。工班看不到廠商，也沒有逐筆核對勾選。整單「確認送出」是最後一次使用者確認，不再增加一般確認彈窗。
4. **既有需求**：草稿續編、修改待審需求及再訂直接開啟第二步。單筆修改在第一步的暫存表單完成後才更新清單，取消會保留原值；永久材料參照、來源單與變更集合仍由既有程式處理。

只在使用自填或材料庫沒有有效廠商、且既有正式驗證要求補齊時，編輯區才保留必要的供應商欄位；不猜測供應商。工班最後確認及未知結果恢復頁皆不顯示廠商。

## 資料與保護

- `EditorState.lines` 仍為待送出清單；選料暫存表單與尚未加入的文字分析結果不會被當成已下單材料。
- 後端 API、Company 隔離、永久 ID、稽核、鎖、退回處置，以及 Orders／Draft_Item_State／Order_History 固定格式未變。
- 整單確認時，仍透過既有 confirmation API 為每筆**目前內容**取得請求綁定憑證；沒有把工班材料全部偽裝成已勾選，也沒有停用伺服器數量與來源驗證。管理員保留逐筆核對。
- 增加同步提交鎖；同一事件內連點送出也只產生一次正式提交。
- 結果 UNKNOWN 或回應缺少可信收據時保留原資料，禁止重送；重新整理只提供唯讀恢復與原作業查詢。
- 明確長度與有效 Pack_Unit／Units_Per_Pack 換算沿用；缺包裝資料要求人工補正。共用交貨備註仍確定性套入所選材料的 Remarks，編輯畫面不重複展開長文。
- 材料資料未讀取成功時顯示錯誤與重新載入入口，不視為空材料庫。
