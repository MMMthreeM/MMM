# 材料分類、搜尋與匯入

Materials 依第一列表頭讀取，可調整欄位順序與插入欄位；既有舊表仍能讀取，未填分類的材料會列為「其他材料」。Price 僅供後端使用，材料 API 不會回傳。

| 欄位 | 用途 |
| --- | --- |
| Item_ID | M1、M2 等短編號。請保持唯一，新增料件使用下一個未使用編號；不要重用已移除編號。 |
| Tags | 以逗號分隔，包含材料用途、字面規格、顏色等搜尋標籤。 |
| Category | 大類，例如電線電纜、燈泡燈管、安裝五金。 |
| Subcategory | 細類，例如管夾、燈座轉接頭；選定大類後可再縮小範圍。 |
| Search_Aliases | 常用叫法，例如黑線、歐姆夾、螺母。以逗號分隔。 |
| Order_Hint | 選料時顯示的叫料說明，例如「1 箱代表整箱」。 |
| Requires_Remarks | TRUE 時，前後端都要求品項備註，草稿與正式單均驗證。 |
| Display_Name | 可選的簡短顯示名稱；Item_Name 仍保留完整規格，訂單使用完整名稱。 |

材料以「名稱＋供應商＋單位」識別。名稱相同但以個、箱下訂時，保持不同編號，不自行換算箱內數量或單價。混合材料依使用者要求保留一項，以「項」計數，完整內容保留於 Item_Name，需在備註確認各項數量。

搜尋會處理全半形、mm²／mm2、吋／英吋、相連的中文與規格，例如「1.25黑線」。多個條件均須符合，名稱完全相符者優先。手機每頁最多 8 筆，桌機（1024px 起）每頁最多 24 筆；申請端不顯示材料編號或供應廠商。

常用材料與最近選用已移除；選料保留分類、關鍵字搜尋與分頁，不再儲存材料偏好到瀏覽器。

更新流程：先備份 Google Sheets，部署相容的新程式，再依表頭更新新版 Materials。歷史資料檔的 Orders 僅含本次整理的 102 張歷史單，請按檔內說明追加一次；如果已匯入早期版本，先按 HIST 編號及材料來源比對，不能整份再追加。舊新材料編號對照另附在 Excel，既有訂單不會因材料編號更換而重寫。

新增分類與標籤不改動原廠商報表對應規則。新供應商或無對應的混合材料，仍須由管理者確認報表格式與規格對應，不能直接套用另一家廠商範本。

驗證：`npm test` 涵蓋欄位相容、價格不外洩、備註必填與搜尋排序。`test:ui` 可用 `UI_CATALOG_PATH` 指定不含價格的材料 JSON，額外驗證真實材料分類、鍵盤選料與手機長文字。

## 2026-10-31：填單、地區與需求狀態一致性

- 文字叫料先逐筆確認，交貨備註及指定對象移到全部材料下方、加入清單按鈕上方。備註對象以獨立留白選項呈現，桌機兩欄、手機一欄；每筆的確認與略過位於同一操作區。最後指定交貨備註不取消已確認材料，加入前仍檢查合併備註長度及其他材料規則。
- 填單成功提示於下一次表單操作或步驟切換時清除。公告內容寬度與頁首一致，手機亦對齊。
- 管理員分析儀表板新增地區篩選；分析及審核皆先地區、再工班，變更地區會清除舊工班條件。分析下探返回會還原地區，切換條件重設分頁／月份範圍。
- 兩頁共用 lib/order-status.ts 的「需求狀態」選項及 lib/order-view.ts 整單篩選邏輯：全部正式需求、待審核、退回待修改、審核中、準備出貨、已送達、全部待處理（含退回）。草稿不納入正式分析／審核。
- 資料庫 Status 與 API 狀態值維持既有值，編輯中顯示草稿；處理中無有效退回原因顯示待審核，有有效原因顯示退回待修改；[已重送] 舊原因不會算成退回。審核中／準備出貨／已送達維持原名，不新增已出貨或已完成狀態。網頁標籤、新單與進度 TG 通知、待審核提醒及新稽核摘要統一使用上述用語。
- 額外 UIUX、資安、效能建議僅列於 docs/optimization-review-2026-10-31.md，尚未實作。
