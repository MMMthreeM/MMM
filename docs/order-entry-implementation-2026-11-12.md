# 下單頁實作與驗收紀錄 — 2026-11-12

依 `order-entry-ux-spec-2026-11-12.md` 及本次「開始依規格修改」指示實作。未部署、未修改正式 Google Sheet。

## 實際修改

- `OrderForm` 仍以既有 `EditorState.lines` 為唯一材料編輯來源。文字整理直接建立未核對材料，不再另設文字材料核對表。
- 預設貼上文字，搜尋選料切換保留內容；選取材料立即加入共同清單。追加文字建立獨立辨識批次；重新整理須明確選擇取代該批次或取消，手動材料保留。若該批次參與尚未保存的合併，先要求撤銷合併。
- 材料列主區保留名稱、廠商摘要、數量及「已核對」。備註與更多操作按需展開；合併／撤銷放入「清單工具」，超過十筆才提供收起的搜尋與待處理篩選。
- 正式核對檢查有效數量、來源、廠商、必要備註及既有材料庫差異；未核對不顯示逐筆紅色警告。實際送出欄位變更才取消該筆核對。
- 兩種來源共用既有最後確認頁，顯示工班、完整材料、數量／單位與實際 Remarks；返回保留表單與核對。沒有新增一般送出確認彈窗，沿用結果待核實及禁止重送保護。
- 文字解析保留小數線徑、顏色、芯數，支援明確長度乘卷數；不再以 Min_Qty 猜測包裝。候選不唯一或非精確名稱／別名時需自行選料。
- 搬運備註預設套用辨識出的線材，在清單只顯示一份共用入口；修改內容／對象會更新實際逐筆 Remarks，並取消受影響筆數的核對。同筆已有另一批次的共用備註時不自動覆蓋。
- 本次樣式由 `components/order-entry.css` 載入，避開現有開發程序曾送出舊全站 CSS 的情況；管理員沿用相同編輯元件及原權限／退回／合併流程。

## 包裝資料契約及維護

Materials 新增**選填**表頭，依 Material_ID／既有 Item_ID 對應材料，位置可重排：

| 欄位 | 意義 | 有效條件 |
| --- | --- | --- |
| Pack_Unit | 一個包裝的單位，例如「箱」 | 非空白，須與原文包裝單位相符 |
| Units_Per_Pack | 一個包裝含多少個該材料 Unit | 有限正數 |

兩欄成對有效才提供包裝換算。缺欄、空白或非法數值視為沒有可靠包裝資料；不讀取 Order_Hint 或 Min_Qty 作為替代。原文和 Unit 相同時直接使用原數量，不重複換算。換算結果仍受原本最低量、級距、數量上限及六位小數規則限制，不把超出精度的值靜默四捨五入。

由材料資料維護者逐項查證真實內含量後，透過既有 Sheet 維護方式填入；本次沒有新增管理頁或寫入任何真實包裝值。缺資料可在該筆人工填每箱數量或最終下單數量，仍須逐筆核對，且不回寫材料庫。測試使用的 12／24 僅為合成值。

Orders、Draft_Item_State、Order_History 固定持久契約未變；辨識原文、批次與共用備註關係屬本頁編輯 metadata，保存只寫入既有七個材料欄位。草稿在同頁保存後保留來源 metadata；重新載入草稿只有既有持久欄位及逐筆 Remarks，不保證重建原文或共用備註分組。若需要跨頁／跨裝置保留來源證據，須另行訂定持久契約。
